# Задача Глушкова для L и X: точный диаметр в Lean 4

**Авторы: S. Uskov, A. Chervov, F. Levkovich-Maslyuk, I. Litvak, A. Smolensky.**
[Авторство](AUTHORS.md) · [English](README.md)
S. Uskov — ORCID: [0009-0006-5845-7013](https://orcid.org/0009-0006-5845-7013).

В Lean 4 формализован точный ориентированный диаметр группы перестановок Sₙ
с двумя генераторами: L — циклический сдвиг, X — обмен первых двух позиций.
Один генератор считается одним ходом. Задача соответствует
[OEIS A039745](https://oeis.org/A039745).

Для каждого целого n ≥ 5:

| Число элементов | Диаметр |
|---|---|
| Нечётное | (3n² − 8n + 9) / 4 |
| Чётное | (3n² − 8n + 12) / 4 |

Главная теорема — [`LX.exact_diameter_all`](LX/SharpDiameterAll.lean).
Доказаны обе границы. Дополнительных комбинаторных предпосылок нет:
условие `NeZero n`, необходимое определению генераторов, следует из n ≥ 5.

Теорема `LX.sharp_route_all` даёт существование слова L/X в пределах этой
границы между любой упорядоченной парой перестановок.
`LX.diameter_eq_max_dist` связывает определённый диаметр с максимумом
ориентированных расстояний по всем парам вершин.

## Проверка

После установки [Elan](https://github.com/leanprover/elan), Git и средств сборки:

```sh
git clone https://github.com/snow-ghost/glushkov-lx-lean.git
cd glushkov-lx-lean
lake exe cache get
lake build LX
lake env lean VerifyLXExact.lean
```

Версии закреплены: Lean 4.34.0 и Mathlib v4.34.0.
Файл `lake-manifest.json` содержит точные ревизии всех зависимостей.

Проверка `VerifyLXExact.lean` контролирует полные типы публичных теорем
и аксиомы всех проектных теорем в цепочке импортов итогового результата.
Разрешены только `propext`, `Classical.choice` и `Quot.sound`.
Использование `sorryAx` или иных аксиом завершает проверку ошибкой.
GitHub Actions повторяет сборку и аудит при изменениях репозитория.

Существование слов доказано классически; отдельного исполняемого алгоритма
поиска кратчайшего слова в пакете нет.
